      Frequently Asked Questions & Architecture

      Everything you need to know about peer-to-peer WebRTC streaming, encryption standards, and zero-cloud architecture.

      How does Direct Beam transfer files without cloud storage?

      Direct Beam creates a direct browser-to-browser WebRTC DataChannel connection. When you select a file or folder, your browser slices data into encrypted 256 KB memory packets and streams them directly to the receiver device via SCTP protocols. Your files are written straight to the recipient's disk and never touch any intermediate cloud servers, databases, or third-party drives.

      Are there limits on batch transfers or maximum file size?

      There are zero file size limitations. Unlike traditional cloud drives that cap single-file uploads at 2GB or 5GB, Direct Beam streams data using native File System Access and chunk backpressure mechanisms. You can easily beam 50GB 4K videos, massive disk images, or batch folders containing thousands of files with full CRC32 data integrity validation.

      How does DTLS 1.3 and WebRTC DataChannel security work?

      Direct Beam connections enforce DTLS 1.3 (Datagram Transport Layer Security) with peer-negotiated ephemeral keys. All traffic across the WebRTC stream is hardware-accelerated and end-to-end encrypted. Even if network traffic is intercepted on public Wi-Fi or cellular networks, the payload cannot be decrypted without the private ephemeral keys generated on your device.

      How does Direct Beam punch through NATs and corporate firewalls?

      Direct Beam integrates automated STUN and dedicated TURN traversal relays powered by Cloudflare Workers Durable Objects. If both peers are on home or office networks, ICE candidates negotiate a direct zero-latency connection. If a symmetric NAT or strict enterprise firewall blocks direct UDP packets, connection automatically falls back to encrypted TURN relays.
