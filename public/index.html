      How it Works & FAQ

      Q1: How does Direct Beam work without cloud storage?

      Direct Beam uses WebRTC DataChannels. Our Render server acts only as a temporary signaling broker to exchange connection handshakes. Once connected, Render disconnects from the flow and files stream directly between device disks.

      Q2: Is there any file size limit?

      No limit. Files are read, sliced, and streamed in memory-safe binary chunks using the Streams API. You can stream 1GB, 10GB, or 50GB+ freely.

      Q3: Why must the sender keep the tab open?

      Because files are not stored on any intermediate server, the sender's browser acts as the direct live host. Closing the tab severs the connection.

      Q4: Can multiple devices download simultaneously?

      Yes. Each receiver who scans the QR or enters the 6-digit code receives an independent WebRTC data pipeline directly from the sender.

      Security & Cryptography

      DTLS / SRTP Transport Encryption

      Direct streams are cryptographically secured at the transport layer using Datagram Transport Layer Security (DTLS). Network sniffers, Wi-Fi operators, and ISPs cannot inspect your packets.

      Zero Server Retention

      No file chunks ever enter server memory or disk storage. Once the WebRTC peer handshake completes, data traverses peer-to-peer over UDP.

      No Logs or Accounts

      Anonymous pairing. No user sign-ups, tracking cookies, or session histories are retained.
